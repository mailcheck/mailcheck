Mailcheck 2.0 adds TypeScript definitions, updates domain matching, and suggests completions for missing domain endings. The existing JavaScript API stays the same.

This is the first beta.

## Email suggestions

- **Leave modern domain endings alone.** An internal IANA snapshot recognizes 1,438 endings separately from the list of correction targets. Addresses at `.ai`, `.io`, `.app`, and other recognized endings are no longer redirected to a different ending just because it looks similar.
- **Recognize more providers.** Defaults now include Proton, HEY, Fastmail, and Tuta.
- **Complete a missing ending.** `sample@gmail` and `sample@gmail.` suggest `sample@gmail.com`. Completion uses the existing `domains` list and requires an exact name with one full-domain match. It doesn't guess from partial names or choose between multiple endings.
- **Stop choosing tied matches by list order.** Equally close full-domain candidates produce no suggestion.
- **Preserve local-part case.** `Sample.Name+Tag@gmial.com` suggests `Sample.Name+Tag@gmail.com`. Only the domain is lowercased; `run()` retains its existing encoding step.
- **Honor a zero distance threshold.** Zero permits exact matches only during distance matching.

Suggestions still go through the existing callback or return value. Mailcheck does not replace the input automatically.

## TypeScript, without a new API

Types are bundled for options, suggestions, custom distance functions, callback return values, and the existing mutable defaults. CommonJS, ESM interop, browser globals, direct source imports, and opt-in jQuery declarations are covered.

Existing JavaScript calls keep the same methods, options, callback arguments, and return shapes. There is no wrapper to adopt or new recognition option to configure. TypeScript consumers of this package don't need a separate `@types/mailcheck` package.

Mailcheck still has zero runtime dependencies and makes no runtime network requests.

## Behavior to check when upgrading

- `gmail.co` is now left alone: `.co` is a real ending. This deliberately favors a missed typo over a wrong suggestion.
- Unknown or ambiguous names without an ending receive no completion. Supplying `domains` still replaces the default list.
- Unicode/punycode domains and unsupported subdomain layouts are left alone rather than guessed at. Explicitly configured compound suffixes such as `co.uk` remain supported.
- Mailcheck is a typo suggester, not an address validator or a deliverability check. A declined suggestion should not block signup.

## Package and coverage

The attached `mailcheck-2.0.0-beta.1.tgz` contains the runtime, minified build, TypeScript declarations, manifests, README, and license. Tests, tools, and vendored jQuery are excluded. The repository's `cut_release.sh` builds local archives for both prerelease and regular versions; it does not publish them.

Coverage includes the original Jasmine suite, regression and package-consumer tests, TypeScript checks, and 60 browser tests across Chromium, Firefox, and WebKit. The browser tests exercise plain JavaScript and the real jQuery example against both runtime builds. Internet Explorer and real email delivery are not covered.

This is a beta archive for integration testing. It has not been published to npm.
